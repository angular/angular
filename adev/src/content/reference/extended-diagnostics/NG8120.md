# Unstable Track Expression

This diagnostic detects object and array literals used directly as tracking keys in `@for` blocks,
including literals surrounded by parentheses.

```angular-html
@for (user of users(); track {id: user.id}) {
  <app-user-card [user]="user" />
}
```

The same problem occurs with `track [user.id]`.

## What's wrong with that?

Each evaluation of an object or array literal creates a new reference. Even if its contents are
unchanged, this reference does not provide a stable tracking key across evaluations.
Unstable keys can prevent Angular from matching items to existing views during reconciliation,
causing unnecessary DOM recreation and loss of DOM state such as focus or text selection.

This check only detects literals returned directly by the tracking expression. It does not infer
instability from an object's type or analyze function implementations. Object references and
function calls can provide stable keys, including Signal Forms field identity references.

## What should I do instead?

Use a stable key that uniquely identifies each item, such as `user.id`:

```angular-html
@for (user of users(); track user.id) {
  <app-user-card [user]="user" />
}
```

## Configuration requirements

[`strictTemplates`](tools/cli/template-typecheck#strict-mode) must be enabled.
This check is **opt-in**: explicitly configure `unstableTrackExpression` as `warning` or `error`
in the project's `tsconfig.json`:

```json
{
  "angularCompilerOptions": {
    "strictTemplates": true,
    "extendedDiagnostics": {
      "checks": {
        "unstableTrackExpression": "warning"
      }
    }
  }
}
```

`defaultCategory` alone does not enable this check, including when it is set to `error`.
This preserves compilation for existing applications that have not opted in.
To disable the check, remove its entry or set it to `suppress`.

See [extended diagnostic configuration](extended-diagnostics#configuration) for more information.

## Related diagnostics

- [NG0956](errors/NG0956) reports full DOM recreation in certain identity-tracking scenarios at runtime.

These diagnostics cover different cases. NG8120 identifies direct object and array literals at
compile time without adding runtime checks or changing reconciliation behavior.
