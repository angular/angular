# Component on ng-container or ng-template

A component's selector matches an `<ng-container>` or an `<ng-template>` in a template.

A component renders its template inside its host element. `<ng-container>` and `<ng-template>` don't render an element, so they can't host a component. In development mode, Angular throws an error when it renders the template. In production mode, rendering fails with a `HierarchyRequestError` from the DOM.

```angular-ts
import {Component} from '@angular/core';

@Component({
  selector: '[app-card]',
  template: `<article><ng-content /></article>`,
})
export class Card {}

@Component({
  selector: 'app-profile',
  imports: [Card],
  // NG8032: Card matches <ng-container>, which doesn't render an element.
  template: `
    <ng-container app-card>
      <p>Profile details</p>
    </ng-container>
  `,
})
export class Profile {}
```

The compiler reports this for `<ng-container>` and `<ng-template>` written in the template. A selectorless component tag such as `<MyComp:ng-container>` is already a template parse error, because these tags can't be used as component tags.

## Debugging the error

Use an element that matches the component's selector:

```angular-ts
@Component({
  selector: 'app-profile',
  imports: [Card],
  template: `
    <section app-card>
      <p>Profile details</p>
    </section>
  `,
})
export class Profile {}
```
