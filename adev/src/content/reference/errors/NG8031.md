# Binding on ng-container, ng-template, or ng-content has no effect

A template puts a binding or an attribute on `<ng-container>`, `<ng-template>`, or `<ng-content>` that can never take effect.

None of these elements renders a DOM element. `<ng-container>` and `<ng-template>` leave at most a comment in the DOM, and Angular replaces `<ng-content>` with projected content. A class, style, attribute, or event binding on them has nothing to apply to, so Angular ignores it.

```angular-ts
import {Component, signal} from '@angular/core';

@Component({
  selector: 'app-item',
  // NG8031: neither binding has an effect, because <ng-container> doesn't render an element.
  template: `
    <ng-container [class.active]="active()" (click)="select()">
      <span>{{ label }}</span>
    </ng-container>
  `,
})
export class Item {
  label = 'Item';
  active = signal(false);

  select() {
    this.active.set(true);
  }
}
```

The compiler reports the following on these elements:

- Class, style, `attr.`, and `animate.` bindings that no directive input claims.
- Property bindings on `<ng-template>` that no directive input claims, such as `[ngIf]` when `NgIf` isn't imported.
- Property bindings on `<ng-container>` under `NO_ERRORS_SCHEMA`. Without that schema, the compiler reports them as unknown properties ([NG8002](errors/NG8002)).
- Event bindings, including `(animate.enter)` and `(animate.leave)`, that no directive output claims and that have no global target such as `window:` or `document:`.
- Static attributes that nothing reads: no directive or structural directive matched the element, the attribute doesn't decide which content projection slot selects the element, and Angular doesn't read the attribute itself, as it does with `i18n`, `ngNonBindable`, `ngProjectAs`, `ngPreserveWhitespaces`, `ngSkipHydration`, and `select` on `<ng-content>`.
- Every binding on `<ng-content>`, which Angular never evaluates.

Bindings that a directive on the element claims aren't reported, and neither are host bindings of directives. A property or event binding named in the selector of a matched directive isn't reported either, because it makes the directive match.

## Debugging the error

Pick the fix that matches what the binding was meant to do:

- **Style or listen to the content**: move the binding to an element inside the `<ng-container>` or `<ng-template>`, or replace it with an element.

  ```angular-ts
  @Component({
    selector: 'app-item',
    template: `<button type="button" [class.active]="active()" (click)="select()">
      {{ label }}
    </button>`,
  })
  export class Item {
    label = 'Item';
    active = signal(false);

    select() {
      this.active.set(true);
    }
  }
  ```

- **Set a directive input or listen to a directive output**: add the directive to the component's `imports`. For example, `[ngIf]` on `<ng-template>` needs `NgIf`.
- **Select a content projection slot**: check that the slot's `select` matches the attribute, and that the element is at the root of the component's content rather than inside another element. Slots match an element with `ngProjectAs` against that value instead of its attributes. For details, see [Content projection with ng-content](guide/components/content-projection).
- **Nothing reads the binding**: remove it.

## Configuring the diagnostic

NG8031 needs [`strictTemplates`](tools/cli/template-typecheck#strict-mode) and is a warning by default. To report it as an error, or to turn it off, set `ignoredBinding` in the `extendedDiagnostics` section of `tsconfig.json`:

```json
{
  "angularCompilerOptions": {
    "extendedDiagnostics": {
      "checks": {
        "ignoredBinding": "error"
      }
    }
  }
}
```

The value can be `"error"`, `"warning"`, or `"suppress"`.
