# Orphaned array field in signal forms

This error indicates that a `Field` instance is no longer an element of its parent array.
Angular signal forms throw `NG01904` when an array field that previously existed can no longer be found in the current collection.

A common trigger is keeping a stale field reference after the array item was removed or replaced with a new object.

## Why this happens

Signal forms track array-of-object items by object identity.
Replacing an item with a new object, or removing it, creates a new field and orphans the previous one.

If code still reads that previous field, for example `field().value()`, Angular detects the mismatch and throws this error.

This can happen when:

- an array item is removed or replaced with a new object
- a `reset()` or `transformedValue()` `format()` function allocates new objects for the same logical rows
- an `@for` block tracks a value on the field, such as `track rowField().value().id`, so reconciliation reads the previous orphaned field

## How to fix it

When iterating signal forms array fields, track by field identity:

```angular-ts
@Component({
  imports: [FormField],
  template: `
    @for (field of form.emails; track field) {
      <input [formField]="field" />
    }
  `,
})
export class App {
  formModel = signal({emails: ['john.doe@mail.com', 'max.musterman@mail.com']});
  form = form(this.formModel);
}
```

Also:

- Re-read fields from the current form tree after structural updates instead of reusing stale references.
- Treat newly formatted objects as new array items. Field identity follows the object instance, not a property such as `id` or `score`.

See [Tracking values for array fields](/guide/forms/signals/field-state-management#tracking-values-for-array-fields).
